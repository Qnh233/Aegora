# Engineering Journal

## 2026-09-04 — LiteLLM immutable image gate

- **Objective / roadmap item:** Start LiteLLM/Langfuse production hardening without depending on the open Workflow or Redis PRs. The first production risk addressed is mutable upstream container tags.
- **Key design decisions / tradeoffs:** Keep the selected LiteLLM digest in the protected GitHub `staging` Environment rather than hard-coding a release in source. Source code enforces the policy (`@sha256:<64 hex>`), while operators can promote a separately tested digest without an application code edit. A mutable `-stable` tag may be useful for discovery, but it is not accepted as the deployment coordinate.
- **Pitfalls / root causes:** The previous compose default used `docker.litellm.ai/berriai/litellm:main-latest`; a deployment could therefore change gateway code even when the Aegora Git SHA did not change. Pinning only a tag would reduce but not remove that drift risk. A first local `bash -n` check also failed because the Windows working tree contains CRLF; this is not representative of the normalized Git blob executed by the Linux Actions runner, so shell syntax must be checked against staged/committed content.
- **Highlights / reusable patterns:** Treat third-party infrastructure images like application releases: discover/test by release tag, deploy by immutable digest. The staging job validates the digest before pulling and inspects it after pull, producing an auditable gateway coordinate alongside the Aegora Git SHA. After startup it also queries authenticated `/v1/models` from inside the LiteLLM container and requires both Aegora aliases, catching config/version incompatibility without issuing a billable completion.
- **Important files / commands:** `.github/workflows/deploy-staging.yml`, `deploy/docker-compose.staging.yml`, `.env.example`, `deploy/README.md`; validate with YAML parsing, digest-policy checks and `git diff --check`.
- **Verification / tests:** Workflow and compose YAML parse passed; static policy checks confirmed the required Environment variable, strict 64-hex digest gate and both required model aliases; `git diff --check` passed. Final pre-commit verification also checks the normalized staged workflow blob with `bash -n` to avoid Windows CRLF false positives.
- **Blockers:** No code dependency on PR #1 or PR #2. A real production digest is intentionally not invented in source; the staging Environment must be populated with an image that has actually passed compatibility verification.
- **Next step:** Extend the compatibility gate with a controlled non-production completion when staging cost credentials are available, then implement provider fallback/budget policy against a verified LiteLLM configuration version.
